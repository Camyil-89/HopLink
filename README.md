# HopLink

HopLink разворачивает цепочку прокси Hysteria2 на Linux-серверах. Desktop-приложение на Go/Wails позволяет хранить серверы и пользователей, собирать цепочку на интерактивной карте и синхронизировать её по SSH.

![Иконка HopLink](assets/hoplink-icon.png)

Основная инструкция на английском: [README.en.md](README.en.md).

## Возможности

- Перетаскивание серверов из библиотеки на карту и соединение узлов в линейную цепочку.
- Назначение входной и выходной точки. Изменение карты через «Применить» обновляет цепочку на серверах и удаляет HopLink с узлов, исключённых из карты.
- CRUD пользователей Hiddify, настройки Hysteria2 и хранение ключа цепочки и TLS-пары.
- Удаление сервисов всех маршрутов на выбранных серверах.
- Зашифрованный `settings.json` сохраняется рядом с запускаемым файлом приложения.

## Запуск в режиме разработки

Требуются Go версии, поддерживающей `go 1.26.0`, Node.js/NPM, Wails CLI v2.15 и WebView2 Runtime на Windows.

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0
Set-Location cmd/desktop
wails dev
```

Чтобы собрать desktop-приложение из корня проекта:

```powershell
node scripts/build-desktop.mjs
```

Исполняемый файл собирается в `deploy/HopLink.exe`.

При применении маршрута приложение запускает `go build` для нужной Linux-архитектуры из исходников в корне проекта (на уровень выше `deploy/`). Go должен быть доступен в `PATH`, а каталог `cmd/hoplink/` и исходники проекта должны находиться рядом с `deploy/`. Собранный `deploy/HopLink-linux-amd64` или `deploy/HopLink-linux-arm64` создаётся заново при каждом применении; Linux-бинарники не встроены в EXE.

На серверах нужны Linux `x86_64` или `aarch64`, доступ по SSH с правами root либо настроенным `sudo`, и открытый UDP-порт (по умолчанию `22033`). Новые SSH host key приложение показывает для явного подтверждения.

Настройки, пользователи, SSH-реквизиты, ключи и карты маршрутов хранятся в зашифрованном `settings.json` рядом с `HopLink.exe`. Храни этот файл как секрет и не добавляй его в Git.

# Релизы

При push или merge в `main` CI собирает `hoplink` и `desktop-hoplink` для Windows, Linux и macOS. Изменения в `cmd/hoplink/` или `internal/hoplink/` создают релиз `hoplink-vX.Y.Z`; изменения в `cmd/desktop/`, `internal/desktop/` или `scripts/build-desktop.mjs` создают `desktop-hoplink-vX.Y.Z`. Изменения `go.mod` и `go.sum` затрагивают оба приложения. Версии независимы и автоматически повышают patch-число от последнего тега соответствующего приложения.

Архив desktop включает исходники Linux-сервиса и Go-манифесты: они нужны для сборки сервиса при Apply. Go должен быть доступен в `PATH` на машине, где запущен desktop.
