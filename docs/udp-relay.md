# UDP-реле и сквозное шифрование

Маршрут: клиент → входное Go UDP-реле → ноль или несколько Go UDP-реле → выходной Hysteria2-сервер → целевой ресурс.

QUIC/TLS соединяет клиент непосредственно с выходным узлом через реле. Клиент шифрует отправляемые данные, выходной узел их расшифровывает. В обратном направлении шифрует выходной узел, расшифровывает клиент. Входной и промежуточные узлы не имеют QUIC-клиентов/серверов и не перешифровывают трафик. Содержимое UDP payload передаётся без изменений.

## Установка из desktop

«Применить» устанавливает `udp-relay` на все узлы, кроме последнего, и `hy2-forward` на последний. Существующие сертификат маршрута, его ключ и активные пользователи устанавливаются на выходе. Старые файлы credentials в каталоге сервиса промежуточных узлов удаляются. Другие маршруты и их файлы не затрагиваются.

Ссылки формируются локально из сохранённого сертификата и входного адреса; для этого больше не нужно читать пароли из серверного журнала. При сохранении входного адреса/домена, порта, SNI, сертификата и паролей строки `hysteria2://` остаются прежними, включая pinSHA256. Меняется сервер, физически предъявляющий тот же сертификат. Перегенерация сертификата или изменение остальных параметров по-прежнему меняет ссылки.

Обновлять нужно всю цепочку через «Применить»: смешивание старых расшифровывающих промежуточных серверов с новыми реле не поддерживается. Существующие соединения во время обновления разорвутся. Desktop проверяет поддержку `udp-relay-v1` всеми загруженными бинарниками до остановки текущих сервисов. Если опубликованный GitHub-бинарник ещё старый, выбрать сборку из текущих исходников.

Пересылка не меняет sysctl, маршруты, qdisc, iptables/nftables, UFW или firewalld. Desktop управляет только файлами HopLink и его systemd-сервисами. Уже существующие правила firewall остаются как есть; UDP-порт должен быть доступен заранее. Автоматическое создание и удаление правил firewall отключено.

## Ручной запуск

Входной/промежуточный узел:

```sh
HopLink -mode udp-relay -hy2-listen :22033 -f NEXT_NODE:22033 -log-level warn
```

Выход:

```sh
HopLink -mode hy2-forward -hy2-listen :22033 -key-file /opt/route/shared.key -hy2-users-file /opt/route/users.txt -hy2-sni example.com -hy2-cert /opt/route/hy2-server.crt -hy2-cert-key /opt/route/hy2-server.key -log-level warn
```

`hy2-enter` оставлен как alias `udp-relay`; прежние флаги для TLS следующего узла (`hy2-upstream-sni`, `hy2-ca`, `hy2-insecure`) удалены. Для ручного вывода ссылок на выходе можно передать `-hy2-public-host ENTRY_HOST`; порт ссылки берётся из `-hy2-listen`. Desktop этот вывод не включает, чтобы ссылки не попадали в journald.

## Изоляция и границы

Каждый исходный UDP IP:port получает отдельный connected upstream-сокет. Следующее реле также различает эти сокеты, поэтому клиенты не объединяются в один общий QUIC-туннель. Connected socket принимает ответы только от заданного следующего узла. Реле пересылает только на заранее заданный адрес, а не на адрес из клиентского payload.

На сессию допускается восемь ожидающих пакетов. Общий бюджет payload в очередях/отправке — 16 МиБ на процесс. Фиксированного ограничения количества сессий нет; реальная вместимость зависит от памяти и доступных сокетов процесса. Idle timeout по умолчанию — 30 секунд, его можно изменить параметром `-relay-idle-timeout`. Память процесса также включает receive buffers, goroutines, сокеты ОС и служебные структуры: 16 МиБ не являются лимитом всей памяти.

При заполнении очереди лишние UDP-пакеты отбрасываются; общий приём не ожидает отправки отдельного клиента. Новая сессия не вытесняет существующие. Ошибка upstream-сокета закрывает только соответствующую сессию. Для создания состояния требуется пакет с формой QUIC Initial v1/v2 размером не менее 1200 байт. Это фильтрация, не проверка подлинности: пароль и сертификат проверяются только на выходном узле. Защита от захвата памяти и сокетов неаутентифицированными отправителями остаётся отдельной задачей.

Каждый переход выполняет UDP receive/send в Go; одна копия payload нужна для отделения очереди отправителя от общего буфера приёма. DNS следующего узла разрешается при запуске. При смене его IP сервис нужно перезапустить. Новый клиентский IP:port должен выполнить новый QUIC handshake: прозрачное QUIC roaming между адресами реле не обеспечивает. Поэтому смена сети клиента требует переподключения; это также относится к очистке старой UDP-привязки.

На выходе включён `IgnoreClientBandwidth` и BBR conservative. Конкретный клиентский BBR-профиль задаётся самим клиентом. Реле не умеют определять учётную запись внутри шифротекста: их лимиты относятся к адресам, не к пользователю. Один пользователь всё ещё может занимать общую физическую полосу или создавать много привязок. Полные пользовательские квоты, защита от flood и гарантии задержек потребуют отдельной работы; эта архитектура устраняет общий межсерверный туннель и повторное шифрование.

## Проверки

В тестах проверяются передача UDP payload без изменений, независимость новых сессий и idle cleanup, QUIC Initial v1/v2, настоящий Hysteria2 TCP/UDP через два последовательных реле с проверкой pin выходного сертификата, продолжение работы второго клиента после отключения первого, сохранение формата ссылок и отсутствие firewall-команд в удалении маршрута. `go test -race` проверяет конкурентный доступ в реализации. Нагрузочные испытания на реальном Linux/VPS и канале выполняются отдельно.
